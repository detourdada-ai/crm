# STEP15-B — 알리고 사업자/테넌트 구조 조사

> 2026-09-05 / CTO. 출처는 알리고 공식 문서와 공개 요금 정보다. **결론(모델 선택)은 내리지 않는다** — CPO/CEO 판단 사항.

## 1. 공식 문서에서 확인된 사실

| 항목 | 확인값 |
|---|---|
| 알림톡 발송 필수 파라미터 | `apikey`, `userid`, **`senderkey`(발신프로필 키)**, `tpl_code`(템플릿 코드), `receiver_1~500`, `message_1~500` |
| 발신프로필 발급 절차 | ① 카카오채널 인증 `POST /akv10/profile/auth/` → ② 카테고리 선택 `POST /akv10/category/` → ③ 심사요청 `POST /akv10/profile/add/` → **발신프로필키 수령** |
| 잔액 조회 | `POST /akv10/heartinfo/` — 잔여 포인트로 발송 가능한 **건수**를 문자 구분별로 반환(`ALT_CNT`/`SMS_CNT`/`LMS_CNT`) |
| 발송 결과 조회 | 목록 `POST /akv10/history/list/`, 상세 `POST /akv10/history/detail/`(mid 기준 수신번호별 상태) |
| 대리점/에이전시(다중 고객사 대신 발송) 정책 | **공식 문서에 명시된 내용이 없음** |

핵심은 **`senderkey`가 계정이 아니라 "카카오 채널 1개"에 종속**된다는 점이다.
그래서 모델 선택은 "누구의 카카오 채널로 나가는가"의 문제가 된다.

## 2. 모델 비교

| | **A. 주문:한장 단일 계정** | **B. 사장님별 알리고 계정** | **C. 플랫폼 계정 + 테넌트별 발신프로필** |
|---|---|---|---|
| 계정 주체 | 주문:한장 | 각 사장님 | 주문:한장 |
| 충전 주체 | 주문:한장(사장님에게 재판매) | 각 사장님 | 주문:한장 |
| 발신자/카카오 채널 | 주문:한장 채널 | 사장님 채널 | **사장님 채널**(테넌트별 senderkey) |
| API 인증 | 키 1세트 | 테넌트마다 키 3개 보관 | 키 1세트 + 테넌트별 senderkey |
| 테넌트 분리 | 불가(모두 같은 발신자) | 완전 분리 | senderkey로 분리 |
| 정산 | 우리가 원가 부담 → 사장님 청구 | 사장님이 직접 결제 | 우리가 원가 부담 → 사장님 청구 |
| 필수 사업자 정보 | 우리 것만 | 사장님 사업자등록증·채널 개설 필요 | 사장님 채널 필요(사업자 정보는 채널 개설 시) |
| 개인정보 책임 | 우리가 수탁 처리 | 사장님 | 우리가 수탁 처리 |
| 운영 난이도 | 가장 쉬움 | 가입 이탈 큼 | 중간 |

**A의 실질적 문제**: 고객이 받는 메시지가 "주문:한장" 채널에서 온다. 반찬가게 고객은
주문한 가게 이름을 기대하므로 브랜드가 어긋나고, 알림톡 템플릿 심사도 발신 주체
기준으로 이뤄진다. 규모가 커지면 발송 책임이 전부 우리에게 몰린다.

**B의 실질적 문제**: 사장님이 알리고 가입 + 채널 개설 + 템플릿 승인을 직접 해야 한다.
"엑셀을 줄여주는 도구"를 쓰러 온 사장님에게 진입 장벽이 과하다. API 키를 우리가
보관하는 문제도 생긴다.

**C가 두 문제를 동시에 피하는 구조**로 보이지만, **공식 문서에 다중 발신프로필 운영·
대리점 정책이 없다.** 이건 문서로 확인이 안 되므로 **알리고에 직접 문의해야 할 항목**이다.

### 알리고에 확인해야 할 질문 (문서로 답이 안 나오는 것)

1. 하나의 알리고 계정(`apikey`/`userid`)으로 **여러 개의 발신프로필(senderkey)** 를 등록·운영할 수 있는가
2. 고객사(사장님) 채널을 우리 계정에 연결하는 절차와 필요한 서류
3. SaaS가 고객사 대신 발송하는 **대리 발송/재판매**가 약관상 허용되는가
4. 포인트 충전이 계정 단위인지, 발신프로필 단위로 분리 가능한지
5. 템플릿 심사 주체(우리인지 사장님인지)

## 3. 가격 — 조사값 (코드·DB에 넣지 않음)

| 메시지 | 공개된 단가 |
|---|---|
| 알림톡 | **알리고 6.5원** (업계 5~15원 분포) |
| 브랜드메시지 | 친구 23~25원 / 비친구 33~35원(딜러 표준 단가) |

용도 구분: 알림톡=정보성(주문·배송·예약), 친구톡=마케팅, 브랜드메시지=이미지·버튼 광고형.

**"원가 × 2" 같은 수익률을 코드나 DB에 고정하지 않았다.** 대신 `message_log`에
`provider_cost` / `platform_fee` / `tenant_charge`를 분리해 두어, 나중에 원가가
바뀌거나 플랜별 무료 건수가 생겨도 스키마 변경 없이 반영할 수 있게 했다.

## 4. 정리

- 기술적으로는 **C가 가장 합리적**으로 보이나, 그 가능 여부가 공식 문서로 확인되지 않는다.
- 따라서 **모델 선택 전에 알리고 문의(§2의 5개 질문)가 선행되어야 한다.** 문의 없이 A로
  가면 나중에 "가게 이름으로 발송"으로 바꿀 때 발신프로필·템플릿을 전부 다시 만들어야 한다.
- 어느 모델이든 코드는 바뀌지 않는다 — `MessageProvider` 인터페이스 뒤에 있고,
  `senderkey`는 환경변수 또는 테넌트 설정 중 어디서 오든 구현체 안에서만 쓰인다.
