## Phase 1 — CEO 실사용 (지금 단계)

하루치 업무를 그대로 해본다: **주문 등록 → 고객 확인 → 배송 정리 → 기사 전달 → 다음날 재처리.**
막힐 때마다 아래 다섯 분류로 한 줄씩 남긴다. 해결책은 적지 않는다(해결책을 적기 시작하면
관찰이 아니라 설계가 된다).

| 분류 | 무엇을 적나 | 예 |
|---|---|---|
| **A. 멈춘 곳** | 다음에 뭘 눌러야 할지 몰라 멈춤 | "주문 등록 후 배송으로 어떻게 넘어가지?" |
| **B. 불안한 곳** | 저장/반영이 됐는지 확신이 안 됨 | "변경사항 저장 눌렀는데 진짜 됐나?" |
| **C. 기존 도구로 돌아간 곳** | 엑셀·카카오·전화가 더 빨라서 이탈 | "이건 그냥 엑셀에서 정렬하는 게 빠른데" |
| **D. 이해 안 되는 용어** | 화면의 말이 내 말이 아님 | "배송 그룹이 정확히 뭐지?" |
| **E. 흐름 불일치** | 제품 순서와 실제 업무 순서가 다름 | "나는 기사부터 정하고 주문을 나누는데" |

### 기록 양식 (그대로 복사해 아래에 붙인다)


## Phase 2 — 실사용자 3~5명 관찰

설문하지 않는다. **"주문 하나 처리해 보세요"** 라고만 말하고 관찰한다.
듣고 싶은 말은 "좋네요"가 아니라 "나는 원래 이걸 ○○에서 하는데"다.

관찰 시 기록: 같은 A~E 분류 + **말한 그대로의 문장**(요약하지 말 것) + 어느 단계에서 나왔는지.

## Phase 3 — 갭 분류

Phase 1·2의 기록을 아래로 분류한다. 이 분류가 곧 해결 방식이 된다.

| 분류 | 뜻 | 대응 성격 |
|---|---|---|
| UX | 기능은 있는데 못 찾음 | 배치·문구 |
| 자동화 | 사람이 반복하고 있음 | 기존 기능 확장 |
| 데이터 | 판단에 필요한 정보가 화면에 없음 | 표시 추가 |
| 연동 | 외부 도구로 나갔다 들어옴 | 연동 검토(큰 결정) |
| 신규 | 현재 구조로 해결 불가 | CPO 판단 필요 |
