## 1. 알리고 공식 문의서 (그대로 발송 가능)

**수신**: cs@alipeople.kr
**제목**: 주문관리 SaaS의 알림톡 연동 관련 사업 구조 문의 (플랫폼/다중 사업자)

---

안녕하세요.
주문·배송 관리 SaaS(서비스명: 주문:한장)를 운영 중이며, 고객사(소상공인 사업자)의
주문·배송 알림을 알림톡으로 발송하는 기능을 준비하고 있습니다.
저희는 **여러 사업자의 발송을 중개하는 플랫폼 구조**라, 개인 사용자와는 조건이 다를 것으로
보고 아래를 문의드립니다. 계약 형태 결정에 필요한 사항이라 가능한 범위에서 공식 답변을
부탁드립니다.

| # | 질문 |
|---|---|
| 1 | 하나의 알리고 계정에서 **여러 개의 카카오 발신프로필(발신키)** 을 등록·운영할 수 있습니까? 개수 제한이 있습니까? |
| 2 | **서로 다른 사업자**(각자 사업자등록번호를 가진 저희 고객사)의 카카오 채널을, 플랫폼인 저희가 **대신 운영·발송**할 수 있습니까? |
| 3 | 사업자별 발신프로필 등록 시 필요한 서류·조건은 무엇입니까(사업자등록증, 채널 관리자 권한 위임 등)? |
| 4 | **플랫폼/대행/재판매 형태**의 발송이 약관상 허용됩니까? 별도 계약(대행사·리셀러)이 필요합니까? |

| 8 | **세금계산서 발행 주체**는 알리고입니까? 저희가 고객사에 재청구할 경우 계산서 흐름은 어떻게 됩니까? |

## 2. 세무 검토 질문서 (그대로 발송 가능)

**전제 설명(세무사에게 먼저 전달할 사업 구조)**
```
· 소상공인 대상 주문관리 SaaS.
· 고객(사장님)이 미리 금액을 결제해 서비스 내 잔액(선불 크레딧)을 충전한다.
· 메시지를 보낼 때마다 그 잔액에서 건당 금액이 차감된다.
· 메시지 발송은 외부 공급사(알리고/카카오)를 통해 나가며, 우리는 그 원가에
  마진을 붙여 고객에게 청구하는 형태를 검토 중이다.
· 현재 결제 금액은 "고객이 실제 결제한 총액(VAT 포함)"으로 기록하고 있다.
· 보너스 크레딧 없음, 잔액 유효기간 없음.
```

| # | 질문 |
|---|---|
| 1 | 선불 충전 잔액의 **부가세 과세 시점**은 충전 시점입니까, 실제 사용 시점입니까? |

| 4 | **미사용 잔액**의 회계 처리(선수금/부채 인식)는 어떻게 합니까? |
| 5 | 환불 시 **부가세 처리**(수정세금계산서 발행 여부 포함)는 어떻게 합니까? |
| 6 | **PG 수수료**는 매출 차감입니까, 별도 비용입니까? 과세 처리는? |
| 7 | 공급사 원가 위에 **플랫폼 수수료(마진)** 를 붙일 경우 과세 구조는 어떻게 됩니까? |
| 8 | **세금계산서 발행 주체**는 누구입니까(우리 → 고객 / 공급사 → 고객)? |
| 9 | 고객이 **개인사업자 또는 비사업자**인 경우 현금영수증 발행 의무가 있습니까? |
| 10 | **장기 미사용 잔액**(유효기간 없음)의 회계·세무 처리는 어떻게 합니까? |
| 11 | **핵심** — 저희가 공급사(알리고) 서비스를 **재판매하는 구조가 가능한 경우와 불가능한 경우**, 각각의 세무 처리가 어떻게 달라집니까? (중개/대행이면 수수료만 매출, 재판매면 총액이 매출이 되는지) |

두 곳에 동시에 보내되 **세무에는 "알리고 답변에 따라 갈리는 질문"임을 명시**하는 편이
왕복을 줄인다(질문서 11번에 그 취지를 넣어 두었다).

## 4. 답변이 오기 전까지 금지되는 것 (재확인)

```
❌ 가격 숫자를 코드·DB·UI에 넣기        ❌ VAT 컬럼 migration
❌ 충전 최소/최대값 확정                ❌ 운영 가격 정책 seed
❌ PG SDK · 결제창 · 실제 충전/환불      ❌ 실제 메시지 발송
```
현재 제품의 정상 상태는 그대로다 — **"설정된 가격 정책 없음" → 발송 없음 → 돈 이동 없음.**

## 5. CTO 판단 — 지금 이 대기 상태가 위험하지 않은 이유

F3D-2까지의 구조는 **가격이 없어도 아무것도 깨지지 않게** 만들어졌다.
정책이 없으면 reserve조차 하지 않고, 업무(주문·배송)는 메시지와 무관하게 끝난다.
따라서 외부 답변을 기다리는 동안 **제품은 계속 정상 동작**하고, 답변이 오면
**정책 행 하나를 넣는 것으로 시작**할 수 있다. 코드 배포 없이 가격이 켜진다.

기다리는 동안 CTO가 할 수 있는 일은 F3D-4 선행 구현이 아니라 **TRACK B·C**다(아래).
