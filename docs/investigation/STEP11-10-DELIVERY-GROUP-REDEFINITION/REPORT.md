### 건물명 정규화 감사
- 전체 82개 distinct 정규화 키 중, 기존 정규화 규칙(공백 제거 + "아파트/apt" 접미사 제거)이 실제로 표기 차이를 통합한 사례는 **3건**뿐(예: "고덕그라시움"/"고덕그라시움아파트"). 나머지는 이미 원문부터 일치한다.
- 정규화로 안 묶인 부분문자열 포함 후보는 **1건**("이편한세상미사" / "이편한세상아파트" — 실제 같은 단지인지 사람 확인 필요, 자동 병합 대상 아님).
- **결론: 새 정규화 규칙을 만들 필요가 사실상 없다.** 기존 규칙만으로 이번 데이터의 표기 차이 문제는 이미 대부분 해결돼 있었다.

## STEP11-10-B — 사장님용 추천 UI 설계 비교

실데이터(2026-08-27, 고덕동 21건 — 고덕그라시움 10건+고덕그라시움아파트 4건=14건 동일단지, 래미안힐스테이트고덕 3건, 나머지 4건 개별)로 안 C와 안 D를 목업으로 비교했다(위 위젯 참고).

| | 안 C(동 섹션 안 그룹 카드) | 안 D(기존 리스트 유지 + 시각 묶음, **권고**) |
|---|---|---|
| 학습 비용 | 새 화면 구조를 익혀야 함 | 기존 화면 그대로, 추가 요소만 인지하면 됨 |
| CEO가 설명한 현재 업무 방식과의 정합성 | 낮음 — "동별로 펼쳐보기"라는 새 탐색 흐름 강요 | 높음 — "한 건씩 보다가 필요하면 묶어서" 흐름 그대로 유지 |
| 낮은 커버리지(36%) 노출 방식 | 그룹 카드가 없는 동은 휑해 보임(안 A/B와 같은 약점) | 개별 리스트가 항상 꽉 차 있으므로 빈 화면 문제 없음 — 그룹은 "있으면 보이는 보너스" |
| 구현 범위 | 리스트 레이아웃을 동 단위로 재구성해야 함(더 큰 변경) | 기존 리스트에 배지/체크박스 프리셋만 추가(더 작은 변경) |

**STEP11-9에서 CPO가 예상한 대로, 안 D가 우세하다.** 특히 CEO가 강조한 "그룹필터를 능동적으로 찾아 쓰지 않는다"는 실사용 패턴에는 안 D처럼 기존 화면 안에 자연스럽게 녹아드는 방식이 맞다.
