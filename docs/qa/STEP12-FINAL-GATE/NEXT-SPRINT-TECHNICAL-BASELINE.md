Draft 반영이 수배로 뛰는 비선형 패턴**이 다시 나타나는지로 본다.

### 1-2. 검증 방식 (신규 QA 작성 시 필수)

Draft 기반 화면은 반드시 전체 흐름으로 검증한다.
```
UI 변경 → Draft 생성 → 변경사항 배너 → 변경사항 저장 → 서버 반영
       → DB 확인 → 새로고침 → 상태 유지
```
"버튼을 누르면 바로 DB가 바뀐다"는 즉시저장 전제를 신규 스크립트에서 쓰지 않는다.
판정은 화면 문구가 아니라 **실제 상태**(요소 존재/가시성, DB 값)로 한다.
저장 후 재생성될 수 있는 식별자(예: `delivery_group_id`)는 **저장 후 다시 조회**해서 쓴다.
