
**날짜 범위 제한이 없으면 156건이 후보가 되고, 있으면 95건이 된다 — 정확히 61건이 오탐이었다.**

즉 **자동 취소를 켜더라도 첫 업로드에서 갑자기 대량 취소가 나는 일은 없다.**

### ① 배송완료가 후보에 잡힌다 — 알고리즘에 제외 조건이 없다
기본 조건(1번)에는 완료 제외가 없어서 **배송완료 주문이 후보 1건으로 잡혔다.**

**후보 목록 단계에서 빼는 것이 맞다.** CPO께서 "배송완료도 제외 방향으로 검토"라고
하셨으므로, 2단계 구현 시 조건에 추가할지 확정해 주시면 반영하겠다.

### ② 배송중은 후보로 잡히되 자동 처리하지 않도록 분리해 두었다
정책 미확정이므로 별도 분류만 한다. 자동 취소 여부는 CEO 판단 사항이다.

### ③ 가장 큰 미해결 — "사라짐 = 취소" 전제가 실측과 어긋난다
CEO 정책 전제는 *"정상 발송 처리되어 사라지는 케이스는 현재 운영 방식상 제외"* 였다.
그러나 실파일에서 조회범위 안인데 사라진 **207건(95+112)이 전부 발송일이 찍혀 있다.**

날짜 범위 제한은 **파일 기간 차이로 인한 오탐(61건)** 만 막을 뿐,
**발송처리로 사라진 건(95건, 112건)은 그대로 후보로 남는다.**

> 지금 정책대로 자동 취소를 켜면, 두 번째 업로드부터 **발송 완료된 정상 주문이 취소된다.**
> 이 전제가 실제 운영과 맞는지 CEO 확인이 필요하다.
